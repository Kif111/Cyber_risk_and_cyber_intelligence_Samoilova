СРО3. OCI (Open Container Initiative)


OCI (Open Container Initiative) — это организация,
которая создала стандарты для контейнеров
(Image Spec, Runtime Spec), чтобы они работали
одинаково везде.

--------------------------------------------------
Что такое образ (IMAGE) и как он собирается
--------------------------------------------------

Образ (IMAGE) — это упакованный «слепок» файловой
системы приложения и его зависимостей. Образ состоит
из слоёв (layers) и метаданных. Каждый слой — это
набор изменений файловой системы, которые накладываются
друг на друга. Слои создаются на этапе сборки: каждая
инструкция в Dockerfile порождает новый слой.
У образа есть уникальный идентификатор — Digest (хеш
SHA256), по которому образ можно найти в реестре.

--------------------------------------------------
Docker Engine
--------------------------------------------------

Docker Engine — это «движок», который управляет
контейнерами. Это не один процесс, а цепочка
компонентов:

  • Docker API — программный интерфейс (REST),
    через который клиент общается с демоном.
  • dockerd — демон Docker, принимает команды от
    клиента и управляет контейнерами и образами.
  • containerd — отвечает за жизненный цикл
    контейнеров и работу с образами.
  • runc — низкоуровневый инструмент, который
    реально создаёт контейнер через механизмы
    ядра Linux (namespaces, cgroups). Соответствует
    OCI Runtime Spec.
  • docker-proxy — компонент, который пробрасывает
    порты между хостом и контейнером.

Цепочка при запуске контейнера:
  docker client → dockerd → containerd → runc → контейнер

--------------------------------------------------
Вывод
--------------------------------------------------

OCI задаёт стандарты, по которым собираются образы
и запускаются контейнеры. Благодаря этому образ,
собранный одним инструментом, можно запустить другим,
и он будет работать одинаково. Docker Engine — это
реализация этих стандартов, состоящая из нескольких
взаимодействующих компонентов.
